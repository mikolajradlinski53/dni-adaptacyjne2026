## Cel

Strona `/harmonogram` pokazuje każdemu pierwszorocznemu jego osobisty plan:
tryb studiów → kierunek → (dla I stopnia) numer grupy → godziny i sale na każdy dzień.
Pod spodem zwinięty pełny rozkład (wszystkie tury i sale). Klik w salę otwiera
okienko z mapą kampusu i podświetlonym budynkiem. Wszystko w PL, EN i UK.

## Architektura

### Dane

- `content/schedule-data.json`: dane bez tekstów, wspólne dla języków:
  - `programs`: `{ code, level: 1|2, groups?: number }[]`
  - `tours`: `{ tour: 1-4, time, slots: { room, program, group }[] }[]` (I st., czwartek)
  - `lectures`: `{ level, date, time, rooms: { room, programs: { code, groups?: number[] }[] }[] }[]`
  - `general`: punkty wspólne (standy, atrakcje, after, UE Party) z `from`/`to`, `date`, `levels`, `id`
  - `online`: `{ level, lang: "pl"|"en", time, href? }[]`
  - `rooms`: słownik sala → `buildings: string[]` (klucze budynków na mapie)
- `content/{pl,en,uk}/schedule-labels.json`: nazwy kierunków (po kodzie), tytuły i opisy
  punktów (po `id`), etykiety dni.
- `src/lib/schedule.ts`: czyste funkcje (bez Reacta):
  `buildPlan({ mode, program?, group? }) → Day[]`, gdzie `Day = { date, items: PlanItem[] }`,
  a `PlanItem = { id, from, to?, room?, highlight? }`. Bez wybranego kierunku zwraca
  ogólny plan (punkty bez sal + informacja „wybierz kierunek”).
- Stary `content/*/schedule.json` i typ `ScheduleEntry` usuwamy po migracji.

### Komponenty

- `ScheduleTimeline` (przebudowa): ModeSwitcher → `ProgramPicker` → lista dni z `PlanItem`.
- `ProgramPicker`: wyszukiwarka + kafelki (akronim i pełna nazwa), potem rząd przycisków
  grup (tylko I st.). Dla niestacjonarnych przełącznik I/II stopień × PL/ANG, zamiast kierunku.
  Link „Nie widzisz swojego kierunku?” prowadzi do `/kontakt`.
- `RoomButton` + `CampusMapDialog`: przycisk z nazwą sali otwiera dialog z mapą i nakładką
  SVG (prostokąty budynków w procentach obrazu). Dialog zamyka się Escape i klikiem w tło,
  a fokus wraca do przycisku.
- `FullSchedule`: zwinięta sekcja (`<details>`). Tabela tur jak w PDF-ie na `sm+`, lista
  per tura na telefonie, do tego tabele sal z prelekcji. Wybrany kierunek i grupa są
  podświetlone.
- Stan: `StudyModeContext` rozszerzony o `program`, `group` i `onlineSlot`, zapisywane
  w localStorage (try/catch jak teraz). Zmiana trybu czyści kierunek, jeśli ten nie
  istnieje w nowym trybie.

### Teksty

- `messages/*.json` → `schedule`: nowa notka (zmiany na Facebooku, bez „godziny wkrótce”),
  etykiety pickera, „Pełny rozkład”, „zbiórka”, „od”, dialog mapy.
- `content/*/modes.json`: skróty i punkty dni zaktualizowane o godziny (strona O wydarzeniu).
- Galeria zdjęć per tryb zostaje bez zmian.

## Obsługa błędów i przypadki brzegowe

- Nieznany kierunek lub grupa w localStorage: ignorujemy i pokazujemy ogólny plan.
- Kierunek I st. z jedną grupą (EKOB, BI, MA): grupa wybiera się automatycznie.
- Zarządzanie w piątek: sala zależy od grupy (1-4 → 1+2 P, 5-7 → 214 A).
- Brak `href` transmisji: tekst zastępczy zamiast linku.
- `prefers-reduced-motion`: bez animacji wejścia (jak teraz).

## Weryfikacja

- Skrypt/test spójności `schedule-data.json`: każda para kierunek+grupa I st. ma dokładnie
  jedną turę, liczba grup w `programs` zgadza się z turami, każdy kierunek ma salę prelekcji,
  każda sala ma budynek na mapie, każdy kod ma etykietę w 3 językach.
- `npm run build` + `npm run lint`.
- Ręcznie w przeglądarce: próbka kombinacji (FIR 5, Z 6, ZIIP 10, MA 1, II st. controlling,
  niestacjonarne II st. ANG), mobile 375 px, tryb ciemny, dialog mapy z klawiatury.
